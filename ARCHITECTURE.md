# ARCHITECTURE

## Stack

| Layer | Choice | Notes |
|---|---|---|
| Shell | **Capacitor** (current major version; Android first, then iOS) | Native wrapper around a WebView, with plugins for device features |
| Build | **Vite** + **TypeScript** | `npm run build` → `dist/`, which `npx cap sync` copies into `android/` and `ios/` |
| UI | Vanilla TS modules + CSS custom properties | Port the prototype's theme tokens (light and dark) as they are |
| 3D | **three** (npm, bundled) | The prototype loads r128 from a CDN. Bundle a pinned version for offline use. Check for API breaks when upgrading from r128 |
| Fonts | Barlow Condensed, IBM Plex Sans and IBM Plex Mono, bundled with `@fontsource/*` | No Google Fonts network call |
| Local data | `@capacitor-community/sqlite` | Hunt log, settings and cached forecasts. Use IndexedDB (`idb`) as the fallback in a browser dev build |
| Device | `@capacitor/geolocation`, `@capacitor/local-notifications`, `@capacitor/haptics`, `@capacitor/preferences`, `@capacitor/share`, `@capacitor/filesystem`, `@capacitor-community/keep-awake` | Use a compass plugin, or `DeviceOrientationEvent`, for heading |
| Sync API (phase 2) | Small REST service: Node (Fastify) + Postgres, Docker Compose, deployed on Coolify | Trent's standard skeleton |
| CI | GitHub Actions | Lint, test, build the web app, then build a signed APK or AAB when a tag is pushed |

## Porting the prototype

The prototype is one IIFE, about 1,900 lines long. Port it in this order. After each step the app should still run.

1. **Move data out of the code.** Turn `FC`, `HV`, `HVY`, `SEAS`, `SUN_CLOSED`, `CWD_MAND`, the WMU GeoJSON and the town list into JSON under `public/data/`.
2. **Move the pure model into `src/model/`.** This covers `sun`, `moon`, `model`, `rutLevel`, `pressure`, `seasonState`, the shot chance and `primeShare`. Add vitest tests that pin today's outputs. For example, the WMU 210 whitetail full day should be about 25%, and WMU 348 on Nov 2, 2026 should show a legal start of 8:11 am.
3. **Port the UI sections** one module at a time, keeping the DOM and CSS as they are.
4. **Replace the hunt log storage.** The prototype calls `window.claude.use('db')` and `use('user')`, which exist only on claude.ai. Swap in `data/db.ts` and keep the localStorage fallback logic.
5. **Bundle Three.js and the fonts.** Then confirm the app runs with Wi-Fi and mobile data turned off.

### Prototype facts to keep
- **Alberta Time is UTC−6 all year from Nov 1, 2026.** There is no fall-back. Use a fixed offset (`TZ=-6`), not the device's time zone database, until the rules settle.
- The season index runs from day 0 = Aug 25 to day 187 = Feb 28 of the next year. Make the year a setting, not a constant.
- `SUN_CLOSED` WMUs: 102–160, 624, 728, 730, 936. Recheck these each licence year.
- Shot-chance calibration: `DAYS_PER_HUNTER=7`, `SHOTS_PER_KILL=2`, `CAL=0.512`. Style multipliers: sit 1, walk 1.6, drive 3. Experience multipliers: average 1, experienced 1.8, pro 2.5.

## Weather

```ts
interface WeatherProvider {
  id: string;
  daily(lat: number, lon: number, days: number): Promise<DailyForecast[]>;   // hi, lo, pop, wind
  hourly?(lat: number, lon: number, hours: number): Promise<HourlyForecast[]>;
}
```

- **Default adapter: Open-Meteo**, using the Canadian GEM model. It needs no key, but the free tier is non-commercial only (see PROJECT, Open decisions).
- **Alternative: Environment and Climate Change Canada.** Use the MSC GeoMet / api.weather.gc.ca city forecasts, which are free under the Government of Canada open licence (attribution required).
- **Caching:** store the last good forecast per town in SQLite with a `fetchedAt` time. Show "as of …" when the forecast is more than 6 hours old. In the field, a cached forecast is better than no forecast.
- **Choosing the point:** use the WMU's nearest town, as the prototype does, or GPS when the user allows it.
- The prototype turns the forecast into weather types (`autoWx`: cold, front, after, warm, normal) and flags snow and tracking days. Keep that logic in `model/`, separate from the adapter.

## Hunt log data model

```sql
CREATE TABLE trips(
  id TEXT PRIMARY KEY, hunter TEXT, wmu TEXT, start_ts INTEGER, end_ts INTEGER,
  style TEXT, notes TEXT, updated_at INTEGER, deleted INTEGER DEFAULT 0);
CREATE TABLE sightings(
  id TEXT PRIMARY KEY, trip_id TEXT REFERENCES trips(id), species TEXT,
  ts INTEGER, lat REAL, lon REAL, count INTEGER DEFAULT 1, sex TEXT, note TEXT,
  updated_at INTEGER, deleted INTEGER DEFAULT 0);
CREATE TABLE settings(k TEXT PRIMARY KEY, v TEXT);
CREATE TABLE wx_cache(town TEXT PRIMARY KEY, fetched_at INTEGER, json TEXT);
```

- IDs are UUIDv7, generated on the device. Use soft deletes and `updated_at` timestamps for last-write-wins sync.
- **Location on sightings is opt-in.** Hunting spots are sensitive, so ask before saving coordinates and never sync them unless the user turns that on.
- Export and import the log as a JSON file through the Share and Filesystem plugins. That way the data is portable even without the sync server.

## Sync API (phase 2)

- `POST /auth/invite` → invite code; `POST /auth/join`; then a JWT is stored in secure storage.
- `GET /sync?since=<ts>` and `POST /sync` exchange rows changed since the last sync (trips and sightings).
- Group model: a **party** (for example, Trent + Zack) shares trips, so each hunter sees the other's sightings.
- Deploy with Docker Compose (api + postgres) on Coolify, behind HTTPS.

## Permissions (Android)

| Permission | When | Why |
|---|---|---|
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | Only when the user taps "Find my WMU" or turns on sighting locations | WMU lookup, sun times for the current position |
| `POST_NOTIFICATIONS` | When the user turns on legal-light alerts | Android 13+ runtime permission |
| `SCHEDULE_EXACT_ALARM` | Avoid it if possible | Inexact alarms within a few minutes are fine for legal-light alerts |
| `INTERNET` | Always | Weather and sync |

There is no background location. Requesting it triggers extra Play review and isn't needed.

## Testing

- **Unit tests:** `vitest` on `src/model/*`, using golden values captured from the prototype.
- **Visual and functional:** Playwright on the web build at 390 px and 1000 px, in light and dark mode.
- **On a device:** a real Android phone with airplane mode on, checking the hunt log, the map and the 3D model.
